# 视觉与文档规范

[文档中心](README.md) / 视觉与文档

目标是让仓库像一个清晰、可信的技术产品：首屏说明定位，中段展示工作流，操作细节进入专项文档。视觉层级不能改变功能边界或验收事实。

首屏使用 `<picture>` 根据阅读环境选择主题，以浅色版本兜底。标记与横幅均为本次文档改版新绘制的自包含 SVG，不是 TestHub 或 k6 的官方标识；不包含真实业务数据、远程字体、脚本或嵌入截图。

## 视觉语言

深色以 `#0B1424` 为底、`#53E1C3` 为强调；浅色以 `#F6F9FC` 为底、`#087D70` 为强调。优先使用留白、清晰标题、细边框和少量功能色，不堆砌 Emoji、发光特效或大量徽章。

品牌句为 **Know your load. Trust your results.** 中文定位强调“从接口准备到结果复盘”。它表达产品目标，不是“所有数据都准确”或“容量已经验收”的证明。

首屏图是工作流示意，必须保留示意性质说明。后续添加真实截图时，应使用合成数据或确认可公开的数据，并说明截图版本与场景。概念稿、实机截图和性能测量不能混用。

## README 结构

顺序保持为：品牌与定位 → 核心能力 → 工作流 → 开始使用 → 支持边界 → 验证记录 → 文档入口 → 贡献与来源。

中文首页保留在 `README.md`，英文入口为 `README.en.md`。操作细节集中在上手指南与既有专项文档；中英文同步能力、依赖和未验收说明，不因翻译删掉限制条件。

徽章只使用可核实的技术栈、许可证或真实自动化状态。没有对应工作流时，不添加“CI passing”；没有部署验收时，不添加“production ready”；不使用编造的用户数量、覆盖率或吞吐上限。

## 发布前检查

确认浅色与深色横幅没有文字截断；在桌面和窄屏检查导航、表格与代码块；检查相对链接、锚点、图片替代文本，以及 `<details>` 是否能展开。

使用 GitHub 支持的 Markdown 与基础 HTML，不依赖任意页面 CSS 或 JavaScript。修改时保留历史验证日期、上游署名及许可证信息。文档渲染检查只证明文档可读，不证明应用测试或部署通过。
