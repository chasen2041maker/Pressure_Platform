# 接口库一键准备与验证

## 使用流程

在“压测项目 → 接口库 / 导入”的压测准备区，选择项目环境和账号池版本。Token 与身份字段只保存账号池中的变量名，实际账号值继续由私有存储按虚拟用户分配。

使用“全选全部接口”选择整个项目，或“全选当前筛选”选择搜索结果。选择可以包含待补齐接口；页面分别列出已选、可验证和待补齐数量。

点击自动补齐按钮保存公共设置并处理选中的接口；没有选择时按按钮标示处理整个接口库。此操作不发送业务请求：自动复用文档默认值、共同认证和可明确推导的成功断言。结果区分别显示配置齐全和仍有缺项的数量，处理数量不代表验证通过数量。

接口的“补齐配置”入口可直接填写路径、查询参数、请求头和请求正文，保存后重新检查。需要真实资源 ID 时填入测试环境中可用的值，或引用已配置变量。高级区可编辑复杂正文和成功断言。保存后再次自动补齐会保留手工设置；接口契约变化时需要打开配置审查后重新保存，不会静默覆盖。

明确声明 WebSocket GET 升级的目录接口可保存原生会话配置，并通过一轮真实 WebSocket 验证复用。通过状态附带实际协议，验证要求完整业务帧和关闭证据；原 HTTP 验证历史不改写，配置修订变化后必须重验。详见 [WebSocket 配置与证据](websocket-scenarios.md)。

登录等存在多种输入模型的接口使用完整 JSON 正文输入框。对象内可引用已配置变量，保存和重新打开保持相同 JSON 类型；未写完的 JSON 会保留在草稿中并阻止保存。历史正文若被错误编码成 JSON 字符串，需要编辑成符合契约的对象后重新保存、验证，平台不会在校验时偷偷改变实际发送的正文。

点击验证时，确认窗口显示实际运行的可验证接口以及跳过的缺项接口。验证使用 k6，以一个虚拟用户、一轮请求运行；包含写操作时需确认本次实际调用范围。返回 HTTP 200 但配置的业务断言失败，会记为失败。没有业务判断依据时，仅 HTTP 成功不能作为业务验证通过。

HTML 或其他文本响应可在高级断言中使用 `CONTAINS`，填写实际响应必须包含的非空文本，例如 `<html`，并保留成功状态码断言。匹配区分大小写，保留期望文本的空格，不把正文解析为 JSON；空白、数字或对象不能作为期望值。该规则验证指定文本确实出现，不代表整份文档内容或资源权限都已覆盖。响应正文继续从调试记录中省略。

每张接口卡片右下角的“测试一次”只执行该接口，与批量勾选无关。先保存接口参数与公共配置，再点击按钮；缺项会阻止执行，写操作沿用范围确认。运行后卡片刷新真实状态，并提供执行详情。网络中断导致结果未确认时，点击“查询本次验证”继续查询原请求，不创建重复任务。

在场景的接口选择窗口选择“复用已验证配置”，可加入单个或多个接口。空白场景采用已验证的环境和身份绑定；存在冲突的绑定会阻止导入，避免悄悄更换测试目标或账号。之后设置并发、轮数或时长，按正常流程发压。

已准备模板可保存一层前置依赖。例如“读取本人客服会话消息”先由同一虚拟用户调用获取/创建本人会话，再提取会话 ID 供目标请求使用。复用模板到任何新场景时会自动展开前置；完全相同的前置只执行一次，冲突输出会阻止导入。每个虚拟用户使用自己的账号行与输出，前置每 VU 一次，不计入业务 TPS，但计入 HTTP 总请求数。前置断言或提取失败时不会执行目标请求。

接口详情与配置编辑器显示前置方法、规范路径、修订和输出名。即使目标是 GET，只要前置含 POST 等写操作，单接口及批量验证都按完整范围确认。选择前置接口本身作为业务接口时，它仍有独立的业务执行和证据；前置成功不能代替它的独立验证。前置模板、环境或账号绑定变化后，旧依赖失效，需审查更新引用并重新验证。

维护 API 在 `preparation.setup_steps` 保存数组，每项只接受 `source_key`、正整数 `revision`、`definition_hash` 和 `extractors`；引用当前项目已准备模板，提取器只接受 `{name, type: "JSON_PATH", expr}` 的基础字段/数字下标路径。`definition_hash` 可从准备摘要读取。最多 8 项，不允许自引用、嵌套依赖、脚本、数组投影、认证覆盖或输出覆盖环境及身份变量。编辑时应原样保留已有数组；省略字段保留原依赖，显式空数组移除依赖并重新检查目标缺项。场景步骤使用展开后的冻结副本，修改或删除其前置后仍须通过运行前检查。

单轮验证同时核对前置和目标的冻结配置、步骤 ID、运行汇总与持久统计。前置必须实际执行一次且断言/提取成功；缺少前置记录、计数不一致或仅有状态码断言均不能让目标通过。验证结果仍只代表当前配置的一用户一轮，不代表全部业务分支或并发容量。

## 新建场景与普通导入默认值

每次新建 K6 场景，页面会读取所选项目已经保存的公共环境、固定账号池版本和 Token / 身份变量映射。没有公共配置时，只选择该项目唯一标记为首选的环境；不会自动选择账号池。切换项目会清除原项目的环境和账号绑定。加载期间已经手工修改的字段保持原值；更换绑定中的任何一项时，不会再自动混入原默认绑定。公共配置失效时需在项目接口库修正后重试。

新场景预填固定并发 1、每用户 1 轮、最长 30 秒、请求超时 30 秒、采样 1 秒和 KeepAlive。SLA 与验收目标均为 P95 不超过 2000ms、错误率不超过 0%，自动熔断关闭；这些值可编辑，是判定条件，不是验证结果。不会猜测 TPS 或其他容量目标。已有场景、复制场景和显式关闭的 SLA 保持原配置。

取消“复用已验证配置”可直接导入原始接口。来源没有人工断言时，自动填入契约唯一明确的成功状态，以及 JSON 响应必需字段中可确定的常量或单值枚举断言；非 JSON、多种成功响应或联合 schema 不强行补业务判断。声明 304 的接口结合步骤与环境的条件请求头判断，条件不明时留待审查。公开接口不新增认证头，无正文的 GET 不新增 Content-Type。手工新建请求预填可修改的 HTTP 200 断言。

来源已有断言、认证头或参数时保留原值。文档默认值按原契约机制生成，示例与真实资源 ID 保留待确认状态；导入不会勾选确认项、触发请求或产生“验证通过”证据。自动断言可在步骤编辑器中修改并再次保存。

场景编辑与保存兼容 JSON_PATH 的 `expr` 和 `json_path` 路径字段，保留来源使用的字段、运算符和期望值类型。调整顺序或其他参数不会改写断言；两个路径字段同时存在却不一致时拒绝保存。未填写完整的断言保留并提示补齐，不会因编辑其他字段而静默删除。

## 结果含义

接口列表默认收起人工准备备注，点击该接口“详情”后展开；配置编辑器保留显示。通过 API 接口管理编辑该接口的 `description`，将备注单独放在 `[压测准备备注]` 与 `[/压测准备备注]` 两行之间，两行缺一不展示，最多显示 4000 字。普通 Swagger 说明不作为备注展示，备注按纯文本显示。写明已确认的原因、执行编号及复用前提；“功能未实现”“待测试数据”“依赖第三方”“协议待适配”应分别记录，不要填写 Token 或其他凭据。

备注只用于说明，不修改接口定义、断言、验证状态或历史证据；修改备注无需重新验证，也不能把失败改为通过。

- 待补齐：有明确配置缺项。
- 待验证：已有配置，还没有与当前版本匹配的成功验证证据。
- 验证通过：本次一用户、一轮请求完成，配置的返回条件满足。
- 验证失败：真实调用或断言未通过。
- 需重新验证：接口定义、参数、环境或账号绑定发生变化。

验证通过不等于容量测试通过，也不表示全部账号均已验证或 Token 永久有效。正式发压仍执行准备检查并记录真实失败。

## 维护约束

验证批次记录模板修订与真实执行的对应关系。只从引擎私有快照、按步骤 ID 的汇总、持久化计数及最终状态得出结果。未执行、超时、停止、数据不完整或快照不一致时不得判为通过。

业务证据可来自实际执行的 `JSON_PATH` 或有效的 `CONTAINS`；仍要求完整单轮成功计数与持久化统计一致。只有状态码断言的结果保持待验证。人工保存文本断言可消除需要人工审查的响应格式缺项，但不会生成通过证据，也不补齐路径、账号或测试数据。WebSocket、SSE、二进制响应及其他断言类型的支持范围不变。

查看、筛选和刷新页面不能启动业务请求。重复提交同一验证请求标识不得创建第二个发压任务。历史场景与执行快照保持自身配置；接口库更新不反向改写历史。
