# 示例业务客服 WebSocket 场景

平台支持有界 JSON WebSocket 会话。下面的频道名和业务消息均为示例，使用前须按目标服务协议修改。

## 支持范围

手工 K6 场景可配置示例业务客服的 JSON 命令协议。每次执行 WebSocket 步骤建立一条连接，首帧认证，然后顺序执行有限条命令，按配置保活后关闭。业务步骤每轮重新连接；前置步骤沿用每个虚拟用户执行一次的规则。混合场景顺序执行，保活期间同一个虚拟用户不会同时执行后续 HTTP 步骤。

第一版不转换 Swagger HTTP 来源或接口准备池的验证证明，不自动重连、重发命令，不包含 SSE、图片分块、二进制帧或命令级 SLA。已有 HTTP 步骤和历史统计保留原含义。

## Bearer 握手与服务端推送

`version: 1` 新增可选 `mode: "PUSH"`；省略 mode 的客服配置仍使用原首帧认证和同 id 回执。PUSH 使用全局每用户 STATIC/BEARER 或 LOGIN/BEARER 账号，把当前访问令牌放入同源握手的 Authorization 请求头，忽略手工 Authorization/Cookie 覆盖；不发送客服 auth 帧，也不向订阅消息补写 id。

每个 `commands` 项是一次有界事件等待：可选 `request` 原样按变量渲染后发送 JSON 对象；省略 request 则只等待。`event_path` 默认为 `$.type`，其值严格等于 `event_type` 后执行 JSONPath 业务断言与提取。至少配置一条断言。匹配 `error_types` 中任一值立即失败；无关帧不能证明成功，连续超过 1024 帧失败。单帧仍限制 128 KiB。缺事件、错误帧、断言失败、提前断开均使会话失败并清空本会话输出，不能把 101 当作业务成功。同执行策略组的后续依赖步骤沿用输出失败阻断和次数预算。

PUSH 的应用心跳必须为 0。服务端协议 ping/pong 由固定 k6 WebSocket 运行时处理。结束时关闭连接，行情订阅随连接注销；不配置一个无回执的 unsubscribe 作为“成功命令”。每轮仍建立新连接，保活期间同 VU 后续 HTTP 不并行；这不等于持续保持 1000 连接的容量证明。

首页 `/api/v1/home/live-teachers/ws` 示例：

```json
{
  "version": 1,
  "mode": "PUSH",
  "auth": {"type": "BEARER", "token": "{{access_token}}"},
  "heartbeat_interval_ms": 0,
  "commands": [{
    "name": "首页直播教师快照",
    "event_type": "home.live_teachers.snapshot",
    "assertions": [{"type": "JSON_PATH", "expr": "$.version", "expected": 1}],
    "extractors": [{"type": "JSON_PATH", "expr": "$.teachers", "name": "home_live_teachers"}]
  }]
}
```

行情 `/api/v1/market/quotes/ws` 将 commands 替换为：

```json
[{
  "name": "行情订阅快照",
  "request": {"type": "quote.subscribe", "codes": ["sz000001"]},
  "event_type": "quote.snapshot",
  "error_types": ["quote.error"],
  "assertions": [{"type": "JSON_PATH", "expr": "$.quotes[0].code", "expected": "sz000001"}],
  "extractors": [{"type": "JSON_PATH", "expr": "$.cycle_id", "name": "quote_cycle_id"}]
}]
```

本人提醒 `/api/v1/me/events/ws` 使用 `event_path: "$.event_type"`、`event_type: "portfolio.reminder.triggered"`；模板断言 `$.data.code == {{reminder_code}}` 并提取 `$.event_id`。必须先有本人真实规则和合法行情触发，建议补充本人规则 ID/修订号断言。连接没有初始帧，单独 PUT 规则也不会产生该业务事件。资源条件未满足时保持未验证，不能用合成推送代替真实业务通过。

前端提供三种推送配置模板，URL 需在步骤中设置。保存、复制和执行快照保留 PUSH 配置，公开报告只保留冻结名称、事件类型和规则编号，不导出令牌或正文。推送计数在 `websocket.events`，客服命令仍在 `websocket.commands`；逐项 `latency_kind: "event_wait"` 表示订阅/开始等待到事件通过的时间，包含业务等待，不是网络 RTT。一个完整会话仍只计一次业务步骤。

本地隔离原生 k6 验收覆盖 Bearer 双账号、无发送初始推送、订阅 JSON 不改写、事件提取到同组 HTTP、每用户次数限制、HTTP 401、握手重定向拒绝、无事件超时和错误事件。保存/复制/私有冻结、公开元数据去凭据及前端模板也有回归；这些合成夹具不计入真实示例业务接口通过数。

## 客服配置约定

场景绑定真实测试环境和账号池，使用全局 STATIC/BEARER 或 LOGIN/BEARER 认证。WebSocket 地址必须与环境同源；HTTP(S) 地址映射为 WS(S)。访问 Token 只出现在认证帧的 `payload.token`，完整引用全局认证配置的访问令牌变量。不得把 Token 放在 URL、普通请求头或业务命令中。

推荐首次验证使用 `/api/v1/support/ws`，认证后读取 `timeline.list`（`channel=demo`、`limit=1`）与 `timeline.unread`（`channel=demo`）。它们不发送客服消息，也不推进已读水位。真实服务允许空历史；空数组本身不代表失败。需要验证具体资源时增加相应业务断言。

每条命令由平台生成独立的请求编号，仅匹配同一编号且 `ok` 严格为 `true` 的回执，随后执行 JSONPath 断言和提取。握手 101、异步推送或其他编号的回执均不能代替业务成功。`{{request_id}}` 在一条命令内保持一致，不同命令重新生成，可用于业务要求的幂等键。

| 配置 | 约束 |
| --- | --- |
| 命令 | 1–64 条；总配置及发送帧均有 128 KiB 上限 |
| 连接超时 | 100–30000 毫秒 |
| 命令超时 | 100–60000 毫秒，认证和业务回执均有期限 |
| 保活 | 0–300000 毫秒，必须短于会话最长时间 |
| 会话最长时间 | 1000–600000 毫秒，不超过场景持续时间 |
| 应用心跳 | 0 禁用，或 1000–60000 毫秒；示例业务建议 25000 毫秒 |

连接和命令超时不能超过场景请求超时。适配器 `0.12.1` 的按时长运行到期后停止接纳新会话，已在窗口内接纳的会话可继续握手、认证和有序业务命令；后继 HTTP 请求或其他 WS 会话仍不得开始。不预留整段会话时长来缩短负载窗口，也不自动重连或重发。

会话工作截止取“本会话开始加原 `max_session_ms`”和“全局负载截止加请求超时加 5 秒、减去 1 秒关闭观察预算”的较早者；连接和单命令仍保留各自原超时。到点失败并发起关闭，只有观察到真实关闭后才完成统计，最多等待 1 秒且不能越过全局收尾期限。回调晚到也检查绝对截止，不能因定时器迟到而伪成功。原会话上限的计时语义保持：工作到点发起关闭，关闭观察仍有至多 1 秒。空闲 hold 和新心跳仍不延长到负载截止之后。

固定轮数的最长时限与零 gracefulStop 保持不变；主动停止、提前关闭、超时和未完成命令仍保留失败或未完成证据。此次会话收尾规则只用于新执行，不更改历史失败记录。

在手工 K6 步骤中选择 WebSocket，加载“示例业务客服只读”模板；模板使用当前全局访问令牌变量。逐命令编辑 JSON、断言与提取器，预期值保留布尔、数字和字符串类型。无效草稿即使处于未选中或禁用步骤也阻止保存，协议转换会保留本地编辑备份。

目录中明确声明 `GET`、`x-websocket: true` 和 `101` 响应的接口，可在“补齐配置”中选择 WebSocket。保存保留原目录地址、来源快照和修订；HTTP 断言须由业务帧断言承接，身份来自公共账号绑定。包含业务发送帧的配置采用原有写操作确认，即使握手方法是 GET。普通 GET 接口不能转换。

接口池验证使用正常 K6 1 VU/1 轮，要求会话、握手、认证、每条声明的命令或事件均成功，并观察到连接关闭。HTTP 101、缺失帧、超时或未关闭均不能作为业务通过。目录显示本次配置的验证协议；既有 HTTP 批次仍保留，不挪用手工 WebSocket 场景历史作为新修订证据。已通过配置沿原“复用已验证配置”入口导入，冻结 WebSocket 合同和来源身份；配置、来源或环境变化使旧证据失效。

## 结果口径

一个 WebSocket 会话计为一个业务步骤，步骤耗时包含连接、认证、命令、保活和关闭。命令响应耗时单独统计；保活不能算作命令响应延迟。混合场景的全局完成速率是 HTTP 步骤与 WebSocket 会话的完成速率，不是消息吞吐量。

HTTP 计数只统计 HTTP 请求。WebSocket 连接、认证、命令、心跳分别统计；当前和峰值连接数来自实际连接事件，不能用虚拟用户数替代。前置仍不进入业务总计。SLA 对整个步骤或全局统计生效，第一版不提供独立命令 SLA。

实时样本最多保存 200 行命令统计并标明截断；不能把未出现的命令推算为零失败或成功。未观察到最终关闭时当前连接数显示未知。报告使用执行时冻结的命令名称，场景后来修改不会改变历史归属。

公开报告只保留步骤和命令标签、规则编号及结果。认证帧及认证回执不显示；第一版业务响应正文也完全省略，服务端错误文本和关闭原因不原样导出。历史执行使用本次冻结的定义，不能从后来修改的场景补写命令内容。

## 验收与发布边界

本地隔离服务用于故障、交错回执、心跳、停止和身份隔离测试；这类测试不代表示例业务业务通过。真实目标验证先固定 1 用户、1 轮，仅使用认证与只读命令，并记录平台执行编号。发布前的直接协议探测须单列，不记为平台执行。

回归入口为 `deployment/test-runner/run_catalog_tests.py`（包含配置、指标、持久化和原生协议夹具），`deployment/test-runner/k6_websocket.test.mjs` 及前端 `websocketStepForm`、`websocketMetrics`、`websocketComponents` 测试。原生协议夹具必须提供固定 `K6_BIN`；缺少二进制时明确跳过，不能将该次 CI 结果当作协议运行验收。所有夹具只访问隔离回环服务、使用合成 Token。




客服发送、评论、回复和反馈会产生真实业务记录。后续写入负载需使用专门测试资源及清理流程；默认只读模板不包含这些操作。当前开发不启动用户保存的 1000 VU 组合场景。
