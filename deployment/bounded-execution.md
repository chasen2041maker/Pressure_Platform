# 同场景有界专项执行

适配器 `0.9.0` / 能力矩阵 `2026-09-20.2`。本地原生 k6、配置、组件及隔离 Docker 验证覆盖以下合同，独立规格和质量审查通过；发布、线上场景整合和真实专项资源验证另行验收。没有启动示例业务负载或修改账号池。

步骤编辑器可开启「专项执行」，保存 `execution_policy`：

```json
{"group_id":"reminders_01","vu_start":1,"vu_end":50,"max_runs_per_vu":1,"min_interval_ms":0}
```

`{}` 保留所有用户每轮顺序执行的历史行为。非空策略仅支持 K6 业务步骤。同组步骤必须连续且五项配置完全一致；最多 128 组，VU 范围不能超出场景并发。VU 仍按原池行序取本人身份，不重新映射或循环复用。

次数是每用户的**尝试上限**。组开始、第一条请求之前消耗一次，失败不返还；间隔限制相邻开始时间。整组共用一次执行决定，不能出现第一步额度耗尽、后续却使用旧输出。新尝试先清除整组输出；失败清除组输出，依赖缺失的后续步骤记为 blocked，独立步骤仍可执行。前置、常量和 CSV 变量可复用；组外业务输出依赖和输出重名冲突预检拒绝。前置与认证步骤不能有专项策略。

例如 1000 个身份按 20 个连续区间分配，每区间 50 VU、每 VU 一次、每组 5 步：最多 1000 次组尝试、5000 次逻辑业务步骤调用。日常步骤仍由 1000 VU 按轮数或时长运行。已有认证刷新可能追加 HTTP 尝试，WS 命令和认证帧另计；组额度不是外部消息数或 QPS。共享资源和真实发送需要单独准备及预算。

预检按实际参与集合和次数预算计算，分别列 HTTP 调用与 WS 会话。间隔或依赖阻断可能使实际次数低于上限；按时长的无限日常步骤仅给启发估计。固定轮数的合法空轮不会导致假「轮数未完成」，但配置参与用户未覆盖、终态缺失、依赖阻断仍不能作为完整成功。单用户调试的 VU 范围也须落在 1 内；验证其他区间请使用对应的隔离场景配置，不能静默重映射原号池。

报告区分执行器轮次、实际业务完成轮次、空轮次、组开始/成功/失败/未完成、实际参与用户、范围/额度/间隔跳过与 blocked。只有实际开始/完成的 HTTP 或 WS 步骤进入原有计数、失败率及耗时。空轮等待并退出业务活跃统计。跳过按每 VU 累计、最多每 5 秒及正常结束时发送，异常停止可能缺最后一批，界面明确标示观测口径。公开工件只保存数字组序号和 VU 范围，不写私有组名、账号、提取值或正文；历史缺失保持未采集。

验证：`test_execution_policy` 使用固定原生 k6、本地隔离 HTTP/WS 服务，覆盖 4 VU × 2 轮日常、1 VU × 1 次专项、失败不返额度、跨轮旧输出拒用、最小间隔、全专项空轮、时长截止、停止及 HTTP→WS→HTTP 同组。`test_execution_policy_api` 覆盖保存、复制、冻结、非法配置回滚与两套迁移；`executionPolicy.test.mjs` 运行真实 Vue 组件逻辑；`k6_execution_policy.test.mjs` 验证累计 skip 事件有界。上述是平台行为证据，不是示例业务 1000 并发容量结论。

## 发布与回滚

升级沿用现有流水线的活动任务检查、停服务、冷备、迁移和历史数据核对。新增 JSON 字段默认 `{}`，原步骤不自动启用专项策略。发布后先核对原场景、账号池、准备配置和执行历史，再通过正常保存及低量执行验收新策略。

`0.8.0` 不识别执行策略，直接回退可能把有限专项恢复为所有用户每轮执行。回滚必须先暂停执行入口和调度，确认 `PerfExecution.ACTIVE_STATUSES`（`PENDING/PREPARING/RUNNING/STOPPING`）均无任务，且没有残留 worker/k6 发压进程。留存待恢复步骤清单，再禁用所有非空 `execution_policy` 步骤；复核其启用数量为零后，才能切换旧镜像。

旧版禁止恢复运行或重试含专项策略的既有私密快照；如需运行，只能从已禁用专项步骤的场景新建执行。保留新增字段、策略配置、历史和账号池，不做逆向迁移。恢复 `0.9.0` 前保持专项步骤禁用；恢复后按留存清单重新启用并预检。首次升级前尚无策略配置时，也要核对这一前提，不能假定所有后续回滚均安全。
